# 网页采集

在想保存的作品、帖子或文章中打开扩展，点击网页采集，检查正文和媒体后保存。选区、选图、剪贴板和截图可以继续补充当前草稿。采集、保存、补采均不调用 AI；手动分析是另一个独立操作。

文章保留文字与媒体顺序；作品说明不自动充当原始提示词。来源明确提供的逐张提示词与相应素材一起保存。视频封面只用于预览，不能代表视频已经保存或可以播放。

## 支持的页面与内容

| 平台 | 提取和播放路径 |
|---|---|
| 小黑盒、微信公众号 | 文章正文与图片；有明确案例标题或编号的多案例图文可在“文章内案例”中分组预览、勾选并分别保存，也可保存整篇文章。小黑盒单案例图片墙与正文提示词保持一组。 |
| 飞书文档 | 提取正文和长文档内容，保留表格内图文、单元格位置及合并关系；无法取得原件的画布内容保留可见快照。未完成的扫描会提示核对。 |
| X | 当前帖正文、媒体和可选引用组；未取得直链的视频，在本次主动采集期间刷新当前帖一次，读取该帖正常加载的媒体响应。优先保存完整 MP4，保留独立播放地址；不会嵌入整条帖子。 |
| 即梦、Higgsfield、LiblibAI、LibTV、Krea | 专门的当前作品或公开内容提取，结合页面媒体与明确的原始提示词。Krea 区分成品与风格参考；LibTV 保留可读取的节点素材，不恢复可运行工程。 |
| ArtStation、Pinterest、Behance | 作品结构与页面媒体结合提取；ArtStation 的可访问官方视频子页面可读取实际视频文件。Pinterest 的已解析图片使用原件候选。 |
| Reddit、微博、小红书 | 当前页面的帖子、正文、图片和可读媒体。登录弹层、折叠评论、不可读的播放器或未加载轮播仍可能需要在原页面处理后补采。 |
| YouTube、Bilibili、TikTok、抖音 | 可读的媒体文件优先保存；来源支持时使用官方独立播放器。Bilibili 保留当前分 P；TikTok 使用视频播放器地址。 |
| 花瓣、Dribbble、DeviantArt、站酷 | 当前作品页面的可见内容及页面提供的结构化媒体。 |
| Midjourney | 按当前作品与所选序号提取图片或视频、原始提示词、参数及视频封面；Explore 提取已加载预览，无原词的条目会标记不完整。 |
| TapNow、Lovart、Civitai、Runway、可灵 | 通用可见内容与结构化图片/视频提取。是否提供提示词、原图、可访问节点或完整视频，取决于当前作品页面；没有提供的内容不会推断生成。 |

不同页面提供的内容可能不同。请打开具体作品或帖子再采集；尚未加载的图片、登录后才能访问的内容和未公开的提示词可能无法保存。

## 普通网页的保存粒度

没有专项适配器的网页，采集预览可选择“整体保存”“按网页分组”或“每个媒体一个案例”。按网页分组使用正文标题层级与媒体顺序，不要求出现提示词；找不到明确边界时保留整体内容。按媒体拆分把图片、动图或视频分别列为案例，同一素材的来源变体与视频封面不会另算一个案例。

切换分组使用当前已取得的内容，不重新扫描。预览中可按媒体拆开一组、合并选中分组或撤回调整；无法明确归属的正文和附件留在“未分组内容”中供选择。公共介绍不会自动变成每个媒体的原始提示词。这些操作发生在保存前，已入库的普通案例暂不提供这一拆分入口。

正文目录的同名文字不会替代章节标题；同一片段出现在多个章节时，各章保留各自的引用，按媒体保存则保留一个独立案例。

普通采集默认只读取当前页面，不等待二级详情。检测到可读取的详情入口后，预览显示默认未勾选的“采集详情信息”；用户勾选才读取媒体卡片明确提供的同站详情链接，以及声明式 GET 详情入口。取消详情读取保留基础结果和人工选择，已完成的补充可以撤回。核对返回页面的主媒体属于该卡片后，保留标题、介绍、制作人员等原文和来源链接，并随所属媒体分组保存。读取进度沿用采集反馈；详情失败保留已采内容并列出缺项，遇到权限拒绝、限流或超时停止剩余详情请求。不会自动提交表单、执行网页脚本或递归遍历链接；仅靠不透明脚本打开、跨站或需额外身份验证的详情仍可能需要手选补充。

普通网页预览优先显示原媒体，来源加载失败才使用单帧截图。资料库可见卡片识别动画容器后使用原文件播放，旧静态缩略图不会替代动图；静态图继续使用缓存缩略图。

普通采集保留正文中已有真实地址、合理尺寸的延迟显现图片；隐藏模板、折叠区域和未加载的轮播仍可能需要回到原网页展开后重新扫描或手选补充。专项网站继续使用各自的提取和文章分组规则。

## 列表批量采集

在列表页切换到列表模式并输入目标数量。采集会继续滚动或翻页，合并重复条目；实际结果取决于页面能提供的内容。保存前可统一选择项目、内容类型和标签，逐条核对后分别入库。扫描结束、停止或没有更多内容时显示实际取得的数量，未取得的案例不会补造。

普通网页可以先手动选取一个示例，再使用列表批量采集。批量范围沿用所选集合及内容层级：只选图片或文字时，不自动扩成整张卡片，也不采集页面上另一个相似集合。手选模板只适用于当前页面；本页不足目标数量时保留实际结果，其他页面需重新选取。刷新、跳转或所选结构失效后会提示重新选择。

手选内容中的明确详情链接也可用于“采集详情信息”。详情提供的视频与当前卡片封面能够对应时，完整视频可以替换缩略图预览，并保留已选状态；页面明确提供的原始提示词随对应视频保存。推荐区或无法核对归属的视频不会加入当前案例。

## 视频与保存结果

- 能取得有效完整视频文件时保存本地；独立在线播放保留原作品地址与单独的播放地址。分段 HLS 使用随扩展打包的开源播放器，音视频在浏览器内处理，不使用外部解析服务。
- 在线视频仍依赖来源可用性。登录失效、链接过期、限流或禁止播放时会显示问题，可回到原作品重新采集；不会用封面或网页嵌套冒充视频播放。
- 案例正文或部分媒体已保存时，未完成的采集项保留供重试，并显示失败原因；全部完成后清空采集预览。已保存的补充文字与图片从草稿中清除，重试补存到同一案例。
- 日常使用不需要卸载扩展或重建案例库。本地版在原目录更新程序，既有案例与媒体继续留在当前浏览器。
