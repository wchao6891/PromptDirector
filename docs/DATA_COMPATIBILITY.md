# 数据兼容与恢复

应用升级继续保留案例、原始媒体、用户编辑、标签、项目、回收站和创作记录。应用版本与数据格式版本分别管理；更新插件不需要常规导出或重新导入资料。

## 分享包

当前版本导出最新格式，同时支持导入已正式发布的历史分享包格式。导入前会检查版本、文件完整性和案例关系，并列出可保留或无法恢复的内容。单个损坏资源不会阻断其他可恢复案例。

## 完整资料夹备份

完整备份用于换电脑恢复，包含回收站以及可读取的本机链接原件。安全合并保留现有资料；精确替换需要完整备份，并在提交前建立恢复点。写入失败或可用空间不足时，原资料库保持不变。

文件夹写入和回读校验通过后才生成完成标记。部分资源损坏的备份可以尝试救援恢复，但不能直接精确替换整库。

## 跨设备同步

同步保留可见的冲突副本，避免覆盖无法确认相同的内容。原设备的安装目录授权不会作为另一台设备的有效授权；升级安装位置与可迁移的案例资料分开保存。

## 中断与重试

导入、恢复或同步中断后，可以继续检查已有结果。无法确定是否成功时会保留相关媒体，避免误删。重复确认不会重复写入相同的案例或再次替换已恢复的资料。

## 容量与原件

分享、备份和恢复支持 ZIP64，实际容量取决于浏览器与设备可用资源。原文件字节与衍生封面分别保存；文件路径、声明大小、校验值和内容关系都会检查。

## 图片内生成信息

新入库图片的可选提取信息随媒体保存；原始工作流留在原图中。分享、备份恢复及同步保留已保存的信息，不读取原图并自动改写历史提示词。人工编辑和清空后不重新填入。

生成信息独立于原文件身份；识别失败保留原图，损坏的提取字段单独报告。详情通过现有来源信息行显示参数，采集来源字段保持原有含义。

较早版本过滤可选参数缓存后，当前详情可按需从该案例原图读取生成信息用于展示。此读取不回写资料、恢复提示词或扫描其他案例；原文件仍是生成信息的来源。

## 贡献者参考

数据结构改动需要补充历史版本迁移及回归测试，并运行 `npm run check:compat` 和 `npm run verify`。版本清单位于 [`compatibility-matrix.json`](../test/fixtures/compat/compatibility-matrix.json)，测试数据来源位于 [`provenance.json`](../test/fixtures/compat/provenance.json)。
