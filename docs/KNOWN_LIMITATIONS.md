# 已知限制与后续增强

## 浏览器无法直接解码的 MPEG-4 视频

PromptDirector 目前依赖 Chrome 的原生媒体解码能力。遇到浏览器无法解码、但系统播放器可以播放的 MPEG-4 文件时，案例仍会保留原文件和来源信息，并提供使用系统播放器打开的路径；当前版本不在扩展内置软件解码器。

后续如实施软件解码，至少需要同时满足以下验收条件：不改变原文件、不会把解码失败误报为导入成功、能中止长时间任务、限制内存与临时存储占用，并在发布包体积与浏览器安全策略检查通过后再启用。

## 超大分享 ZIP 的导出前容量预检

分享 ZIP 导入会按文件数量、单文件大小、总大小和元数据大小执行安全校验；当前导出流程还没有在写包前复用全部同一套估算，因此极大资料集可能在接收方导入时才发现超过边界。完整资料库迁移请使用完整资料夹备份，不要把单个超大分享 ZIP 当作灾难恢复备份。

后续增强应让导出与导入共享同一容量计划，在开始生成前列出超限项并阻止产生无法导回的包；不能只放宽限制或在导入端静默丢弃内容。
